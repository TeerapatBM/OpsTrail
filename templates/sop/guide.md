- **ผู้อ่านเป้าหมาย**: วิศวกรในทีมที่ไม่เคยทำงานนี้มาก่อน ต้องทำตามได้ทันทีโดยไม่ต้องถามใคร
- **Purpose / Scope**: 2–4 บรรทัด บอกว่าใช้ SOP นี้ในสถานการณ์ไหน และอะไรที่ไม่ครอบคลุม
- **Prerequisites**: สิทธิ์ (role/group), เครื่องมือ + เวอร์ชันที่เห็นจาก source, การเชื่อมต่อ (VPN/jump host) ห้ามใส่ password/token — บอกแค่ว่าเก็บไว้ที่ไหน
- **Procedure** (หัวใจของเอกสาร):
  - 1 ขั้น = 1 การกระทำที่ตรวจผลได้ ตั้งชื่อขั้นเป็นคำกริยา เช่น "ติดตั้ง Universal Forwarder"
  - ใช้คำสั่งจริงจาก source เรียงตามลำดับที่สำเร็จ ตัดคำสั่งที่พิมพ์ผิด/ลองแล้วไม่ได้ออก (ถ้าเป็นบทเรียนให้ย้ายไป Troubleshooting)
  - แทนค่าที่เฉพาะเครื่อง/ลูกค้าเป็นตัวแปรที่อธิบายไว้ เช่น `<SPLUNK_HOST>` ถ้า SOP ควรใช้ซ้ำได้
  - ทุกขั้นมี "ผลลัพธ์ที่คาดหวัง" และใส่ screenshot ถ้ามีใน source
- **Verification**: วิธียืนยันว่าทำสำเร็จ (คำสั่งตรวจสถานะ, หน้า UI ที่ต้องเห็น)
- **Rollback**: ขั้นตอนย้อนกลับถ้าเกิดปัญหา ถ้าไม่มีข้อมูลให้ใส่ `[TODO]`
- **Troubleshooting**: ดึงจากคำสั่งที่ FAILED และโน้ตของ user ใน source
- **Revision history**: version 1.0 วันที่ทำงานจริง
